# Network stack survey across IoT, industrial and general-purpose networks

[中文](network-stacks.md) · [Network groups and service boundaries](network-groups.en.md)

Before connecting a Thread thermostat, find out what the device exposes. A border router can carry IPv6 packets to it. If the thermostat implements only Matter, a plugin must join the authorized fabric as a controller to read its temperature. A Modbus TCP meter on Ethernet presents a similar distinction. **Address reachability, exchanging device-protocol messages and establishing a rutis session are three separate conditions.** [Thread border router](https://openthread.io/guides/border-router) · [Matter](https://csa-iot.org/all-solutions/matter/)

This inventory covers common, sector-specific, unusual and legacy networks by **protocol family and observable handoff**. A deployment can span several rows for access, IP adaptation, transport and its device model. The tables identify representative protocols and significant variants. Vendor extensions, new versions and new combinations can be classified by the same method. Each row ends with an integration judgment and representative primary sources.

## How many network protocols are there?

This survey groups protocols into 52 entries by the interface a plugin encounters. Counting parseable wire protocols and formats yields a scale of thousands. Three reference counts checked on November 27, 2026 illustrate the difference.

| Source | Count | What one item represents |
| --- | ---: | --- |
| IANA IP Protocol Numbers | 148 numbered entries | IPv4 Protocol and IPv6 Next Header share an eight-bit number space. The registry lists 0–147 individually, including extension headers and historical uses. At the time, 148–252 were unassigned, 253 and 254 were for experiments, and 255 was reserved. [Registry](https://www.iana.org/assignments/protocol-numbers/protocol-numbers.xhtml) |
| Wireshark 4.6.10 | About 3,000 | Decoder coverage reported in the official introduction. The alphabetical index enumerates 2,166 filter keys, of which 2,056 have version ranges that include 4.6.10. [Official index](https://www.wireshark.org/docs/dfref/) · [50 family groups and support decisions](wireshark-support.en.md) |
| IANA Service Names and Port Numbers | 7,336 distinct service names | Drop blanks and deduplicate the CSV's `Service Name` column, counting a name registered for both TCP and UDP once. Multiple names can use one protocol. Serial, non-IP and private protocols may have no entry. [Registry CSV](https://www.iana.org/assignments/service-names-port-numbers/service-names-port-numbers.csv) |

For MQTT over TLS over TCP, the IP header identifies TCP. A packet analyzer can have separate parsers for TCP, TLS and MQTT, although observing MQTT in that trace requires decryption. The three counts overlap and cannot be added to produce a protocol total.

Several areas in the catalog merit finer distinctions when building network plugins. BFD observes forwarding-path liveness. IGMP/MLD signal local multicast reception interest. PIM-SM builds multicast distribution paths between routers. RPKI-to-Router supplies data for validating route origins. TACACS+ supports administrative access to network devices. Each can substantiate only part of a claim that a node is reachable and trusted. [BFD](https://datatracker.ietf.org/doc/html/rfc5880) · [PIM-SM](https://datatracker.ietf.org/doc/html/rfc7761) · [RPKI-to-Router](https://datatracker.ietf.org/doc/html/rfc8210) · [TACACS+](https://datatracker.ietf.org/doc/html/rfc8907)

**How to read the catalog**

- **The system exposes IP.** Reuse an existing TCP, WebSocket or gRPC link when the actual peer implements the same protocol, has the resources and admits the connection. Sleep cycles, NAT and isolation policies can still restrict reachability.
- **Both endpoints expose a programmable channel.** Verify reliability, order, duplex behavior, message boundaries, payload budget, backpressure and closure for the selected profile. Frame byte streams and supply any missing guarantees for raw frames. Admit the peer before calling `rutis/sessions.open(far)`.
- **The device exposes objects, commands or resources.** A Go controller or gateway plugin speaks the native protocol and exports properties, events or operations to rutis. The gateway can host the rutis peer while the device continues to run its own protocol.
- **The network exposes topics, datagrams, short messages, one-way broadcasts or deferred delivery.** Offer publish, receive, queue, expiry or receipts according to its actual contract. Record link acknowledgment, next-hop acceptance, destination receipt and business execution separately. Preserve time-critical loops on the field controller.

The implementation baseline is rutis 0.23.0. This repository already has Go plugins for TCP, SSH, Cloudflare, Tailscale, gRPC and libp2p. Integration choices below are research judgments. Other device and protocol profiles require separate hardware or implementation validation. [Plugin guide](../guide/link-plugins.en.md) · [Link contract](../design/01-link-plugin-contract.en.md)

## 7. Verify the boundary on complete stacks

| Actual path from device to plugin | Peer and acceptance check |
| --- | --- |
| Thermostat → 802.15.4 → Thread (6LoWPAN/IPv6) → border router → Matter controller plugin | The authorized controller reads an attribute in the fabric. Test IP reachability without Matter operation authorization, then an authorized sleepy device. The two failure causes should be distinguishable. |
| Zigbee contact sensor → Zigbee endpoint/cluster → coordinator or gateway → Go plugin → rutis event | After a device rejoins, resolve it to the original sensor by device and endpoint. Verify that a reused short address does not misattribute subsequent readings. The application decides whether an open door warrants an alarm. |
| Meter → LoRa/LoRaWAN Class A → radio gateway → network server → application server → Go messaging plugin | Normal downlink windows follow uplink. Expire one downlink request, then require separate evidence for enqueue, MAC acknowledgment of a confirmed downlink and the device application's response. The cloud-side connection can remain live while the meter still works in windows. |
| Instrument → RS-485/Modbus RTU → master or RTU/TCP gateway → Go Modbus plugin → rutis service | Test a reachable gateway with an unresponsive instrument, then verify device address, register mapping, timestamp and units. A successful TCP connection cannot establish measurement freshness. |
| Controlled edge device → Wi-Fi HaLow or cellular IP → TCP/mTLS → rutis link → cloud plugin | Both endpoints implement the protocol. Check frame limits, sleep or handover, reconnect and cleanup. Independently determine whether a job ran before the connection recovered. |
| Field node → intermittent radio or satellite short messages → forwarding store → cloud inbox plugin | Test with endpoints that are never online together, duplicate delivery and expiry. Correlate business processing receipts by device event ID. |

These are proposed experiments requiring hardware or a testbed that faithfully reproduces the profile. A Go plugin can run wherever the controller SDK, kernel driver or gateway API is available. The operator owns commissioning, pairing, key installation, radio settings and carrier provisioning. The appropriate application owns business membership, interpretation of device units, task permissions and business receipts.

**Record six things for a new stack.** Describe the deployed layers from medium to device model, the interface handed to the plugin, the protocol termination point, forward and return delivery guarantees, where identity and keys are verified, and timing or resource limits affecting reachability. Add an observation that would disprove successful integration, such as a reachable IP endpoint with an unreadable resource or an accepted request with an expired downlink. This lets a new vendor profile be assessed for the network capability it actually adds.
